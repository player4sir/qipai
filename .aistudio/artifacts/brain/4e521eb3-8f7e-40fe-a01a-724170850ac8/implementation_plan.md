# 游戏场景房卡与台面积分纯净对接方案

将入场面板（`RoomEntryManager`）确认的房卡预冻结、初始积分与房间底分实际贯通至五大游戏牌桌场景（普洱麻将、斗地主、抢庄斗牛、经典金花、云南捞腌菜），同时剥离牌桌内一切非必要的悬浮状态条与常驻补分按钮，让画面100%聚焦于牌局本身。

## User Review & Critical Decisions

> [!IMPORTANT]
> 以下为您在第一阶段确认的核心设计准则，本方案严格遵照执行：

- **Confirmed Decision 1（牌桌纯净视觉）**：彻底移除牌桌顶部的“房卡预冻结悬浮横幅”与右上角的“底分/初始分/台面分/核销状态”复合悬浮条，仅在各游戏牌桌原生信息区展示底分，在各座位头像面板展示实时台面积分。
- **Confirmed Decision 2（全员同步初始分与底分结算）**：本桌全体入座玩家（含房主、加入玩家与AI对手）统一按入场面板确认的「初始积分」同步开局，单局输赢严格按「所设底分 × 牌型/番数倍数」实时增减台面分（零和封顶、不穿仓）。
- **Confirmed Decision 3（破产补分按需触发）**：正常打牌过程中隐藏所有补分入口与多余控件；仅当某局结算完毕且玩家台面积分低于房间底分时，自动弹出简洁协调的「房卡补分续局」面板。

## 1. Overview & Core Concept

- **What It Does**：打通从大厅入场配置（`RoomEntryManager`）到五大游戏牌桌（服务端房间引擎 + 客户端牌桌视图）的数据闭环，使玩家自定义的底分、初始积分、局数与扣卡方式在牌局中真实生效。
- **Target Audience / Persona**：追求纯粹、沉浸、符合商业棋牌标准体验的棋牌玩家。
- **Key Value**：消除牌桌内杂乱的调试感浮层与冗余文字，使积分账目清晰透明、房卡核销静默可靠、牌桌视野开阔专注。

---

## 2. User Experience & Visual Design

- **Key User Flows**：
  1. **入局数据直通**：玩家在 `RoomEntryManager` 确认底分（如 `200`）、初始积分（如 `5000`）与局数后进入牌桌，牌桌中央/原生顶栏立即显示当前底分 `200`，全体座位头像下方积分统一初始化为 `5,000`。
  2. **无干扰沉浸打牌**：首局发牌时服务端静默完成预冻房卡核销（发牌前退房自动全额退还），牌桌上方不再弹出“已预冻X张房卡/立即发牌”横幅，右上角也不再堆叠“底分/初始/台面/核销”胶囊。
  3. **单局零和积分变动**：每局结束时，根据各游戏规则（斗地主叫分×炸弹倍数、麻将番数、斗牛牌型倍数×庄闲倍率、金花底池、捞腌菜倍数）乘以房间底分计算本局输赢，实时更新各座位台面积分。
  4. **局间破产保护补分**：仅当单局结算后玩家座位台面分低于当前房间底分、无法继续下一局时，系统按需弹出简洁的商业化房卡补分面板（支持 `1x 标准补分` 与 `2x 双倍补分` 或离桌结算）。
- **Visual Identity & Theme**：
  - *Aesthetic Direction*：商业级沉浸式棋牌牌桌，克制、聚焦、零冗余浮层。
  - *Color Palette & Mood*：60% 经典牌桌绒布基底（墨绿/深棕） + 30% 原生木质与黑金座位框 + 10% 琥珀金（`#F59E0B`）高亮关键数字。
  - *Typography & Hierarchy*：牌桌底分与座位台面积分统一使用等宽数字（`font-mono tabular-nums`），避免数字跳动引发视觉位移；严禁任何文本 Emoji 或字符符号。

## 3. Key Product Decisions & Trade-Offs

- **Decision 1：静默化两阶段房卡核销（移除牌桌顶部预冻横幅）**
  - *Chosen Approach*：首局发牌瞬间由服务端房间引擎自动触发 `captureEscrowOnFirstRound` 完成核销；若发牌前玩家点击牌桌左上角“返回大厅”，服务端自动全额退还预冻房卡并仅在大厅轻提示告知。
  - *Why*：入场前已在 `RoomEntryManager` 完成二次确认，牌桌内再挂横幅会遮挡上家手牌与牌桌顶部区域。
- **Decision 2：统一五大游戏 AI 与玩家起始台面分**
  - *Chosen Approach*：修正炸金花（`ZhajinhuaRoom`）中 AI 随机带入筹码及抢庄斗牛（`NiuniuTableView`）本地回退状态写死 `128000` 积分的问题，强制所有座位起始台面分等于本桌 `initialScore`。
  - *Why*：保证商业房卡局全员起点绝对公平一致，账目零和清晰。

## 4. Technical Architecture & Data Strategy *(Technical Reference)*

- **Architecture & Component Diagram**：

```
┌─────────────────────────────────────────────────────────────────────────┐
│                     RoomEntryManager (App.tsx 顶层)                     │
│   确认参数: gameType, mode, baseScore, initialScore, totalRounds, payMode │
└───────────────────────────────────┬─────────────────────────────────────┘
                                    │

│                   Server RoomManager & RoomCardEngine                   │

│  • 全员座位 (玩家 + AI Bot) 统一初始化 beans = confirmed.initialScore   │
│  • 单局结算严格按 confirmed.baseScore × 倍数 实时增减各座位 beans       │
└─────────┬───────────────┬───────────────┬───────────────┬───────────────┘
          │               │               │               │

   │ 原生底分区 │  │ 原生底分区 │  │ 原生底池区 │  │     原生底分区     │
   │ 座位积分栏 │  │ 座位积分栏 │  │ 座位积分栏 │  │     座位积分栏     │
   └──────┬─────┘  └──────┬─────┘  └──────┬─────┘  └─────────┬──────────┘

                                  ▼
                 ┌─────────────────────────────────┐
                 │  SharedTableHudOverlay (精简版) │

                 │  • 按需弹出破产保护房卡补分面板 │
                 └─────────────────────────────────┘
```

- **Interactive Component & State Mapping**：
  1. **顶层参数透传**：`App.tsx` 保存最新确认的入场配置（`activeEntryConfig`），在发射 `c2s_quick_match` / `c2s_create_room` 时完整携带 `baseScore`、`initialScore`、`totalRounds`、`payMode`，并将 `baseScore` 与 `initialScore` 作为初始属性传入各牌桌视图组件。
  2. **服务端全员同分初始化**：`server.ts` 及五大房间类（`DdzRoom`、`MahjongRoom`、`NiuniuRoom`、`ZhajinhuaRoom`、`LaoYanCaiRoom`）在创建房间、匹配入座及填充 AI 机器人（`addBotPlayer`）时，统一将所有座位的 `beans` 设定为本桌 `initialScore`。
  3. **牌桌浮层彻底瘦身**：在 `SharedTableHudOverlay` 中移除预冻结提示横幅、右上角复合底分/台面/核销状态栏及常驻补分按钮；仅保留断线重连提示、快捷语/互动道具与 `s2c_bankruptcy_prompt` 触发的破产房卡补分模态框。
